ChangeProof is an evidence-producing maintenance workflow for brownfield applications. It discovers the real blast radius of a change, tests what can be tested, separates observation from inference, and refuses to pretend target-platform validation happened when it did not.

One small ticket. A much larger change.

ORDERPRO is a fictional IBM i order-processing system deliberately built like a real brownfield estate: business rules cross modern and legacy components, some documentation is stale, and not every validation can happen on a developer laptop.

Baseline

  • Preferred orders at 17:00 fail
  • API cutoff is hard-coded to 16:00
  • RPG logic has no Preferred branch
  • Docs contain stale customer-class semantics
  • Fulfillment batch is scheduled at 18:00
→

Post-change

  • Preferred 17:00 orders pass
  • Standard 17:00 orders still fail
  • RPG/API rules distinguish customer class
  • Tests and docs are updated
  • Fulfillment batch moves to 18:15
The useful surprise: CHG-0042 never mentioned the batch schedule. ChangeProof inferred that a batch beginning at exactly 18:00 could collide with the new 18:00 acceptance window. That downstream operational consequence became part of the actual remediation.
